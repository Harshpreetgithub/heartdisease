# HDP — Heart Disease Predictor

A small, complete, deployable version of your `Heart_Disease_Prediction_-_Classification.ipynb`
notebook: the same preprocessing and Random Forest model, wrapped in a FastAPI
serverless API and a static web form, ready to deploy on Vercel.

**Live pipeline:** patient chart form → `/api/predict` (FastAPI on Vercel) →
scikit-learn Random Forest → probability of heart disease.

## Results (held out from `data/heart.csv`, 918 records)

| Metric | Value |
|---|---|
| Test accuracy | 88.04% |
| Test F1-score | 0.891 |
| 10-fold CV accuracy | 87.60% |

These match the notebook's own comparison table — Random Forest was the
best of the five models it tried (Logistic Regression, KNN, SVM, Decision
Tree, Random Forest), so that's the one shipped here.

## How the model works

This reproduces your notebook's pipeline exactly:

1. `Sex` and `ExerciseAngina` are label-encoded (`M`→1/`F`→0, `Y`→1/`N`→0).
2. `ChestPainType`, `RestingECG`, `ST_Slope` are one-hot encoded with
   `drop_first=True` (dropping `ASY`, `LVH`, `Down` as reference categories).
3. Features are scaled with `StandardScaler`.
4. A `RandomForestClassifier(n_estimators=100, random_state=0)` is trained
   on an 80/20 stratified split.

`api/index.py` re-implements step 1–2 manually (no pandas needed at request
time, which keeps the serverless function small and fast) using the exact
column order saved in `feature_columns.json`, then applies the same scaler
and model.

## Run it locally

```bash
# 1. Install dependencies (includes pandas, for training)
pip install -r requirements-dev.txt

# 2. (Optional) retrain the model — already-trained artifacts are included
python model/train_model.py

# 3. Copy fresh artifacts into api/model/ if you retrained
cp model/model.pkl model/scaler.pkl model/feature_columns.json api/model/

# 4. Run the API locally with the Vercel CLI (recommended — matches prod)
npm i -g vercel
vercel dev
```

Then open `http://localhost:3000` and fill in the form.

## Deploy to Vercel

**Option A — Vercel dashboard (easiest):**
1. Go to [vercel.com/new](https://vercel.com/new) and import the `HDP`
   GitHub repo you just pushed.
2. Framework preset: leave as **Other** (no build step needed).
3. Deploy. Vercel will pick up `vercel.json`, `requirements.txt`, and
   `api/index.py` automatically.

**Option B — CLI:**
```bash
npm i -g vercel
vercel login
vercel --prod
```

Once deployed, your form at `https://<your-project>.vercel.app` will POST
to `/api/predict` on the same domain — no CORS setup needed.

## API reference

`POST /api/predict`

```json
{
  "age": 54,
  "sex": "M",
  "chest_pain_type": "ATA",
  "resting_bp": 130,
  "cholesterol": 246,
  "fasting_bs": 0,
  "resting_ecg": "Normal",
  "max_hr": 150,
  "exercise_angina": "N",
  "oldpeak": 1.0,
  "st_slope": "Up"
}
```

Response:

```json
{ "prediction": 0, "label": "No Heart Disease Indicated", "probability": 0.12 }
```

`GET /api/health` → `{ "status": "ok", "model_loaded": true }`

## What would make this a stronger portfolio project

- Add input validation on the frontend that mirrors the API's Pydantic
  constraints, so errors show up before the request is even sent.
- Add a `tests/` folder with a couple of `pytest` cases that hit
  `build_feature_vector()` directly and assert the encoding for each
  categorical field is correct — cheap insurance against a refactor
  silently breaking the column order.
- Track experiments (which model, which hyperparameters, which score) in
  `model/metrics.json` over time instead of overwriting it, so the README
  table can cite a real history.
- Consider adding a rate limit or simple API key check on `/api/predict`
  before sharing the live link widely, since it's an unauthenticated
  public endpoint.
